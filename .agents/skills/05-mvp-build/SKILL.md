# 최소 기능 구현

## 입력
P0 기능 목록/인수 기준, 검증 계획, 기존 프로젝트 코드, 설치·규정 제약.

## 절차
1. 현재 브랜치/변경 내역, 런타임, 기존 실행/테스트 명령어를 확인하고 작업 범위를 알린다.
2. 가장 짧은 **입력→처리→출력** 수직 슬라이스로 P0를 나눈다. P1/P2보다 P0를 우선한다.
3. 첫 슬라이스만 최소 파일 변경으로 구현한다. 기존 코드와 패키지 재사용을 우선한다.
4. 실제 제공 데이터/명확한 입력 스키마로 테스트한다. 테스트용 합성 데이터가 필요하면 명시적으로 구분하고 실제 성능 근거로 사용하지 않는다.
5. 구동·테스트·실패 메시지를 확인하고, 실패하면 `debug-recovery` 절차로 원인을 좁힌다.
6. P0 항목별 완료 판정 체크 후 다음 슬라이스로 이동한다. P0 통과 전 P2에 시간을 쓰지 않는다.
7. 매 단계 수정 파일, 실행 명령, 테스트 결과(성공/실패/미실행), 남은 위험을 요약한다.

## 출력
- 구현한 기능과 관련 REQ-ID
- 변경 파일 목록과 재현 명령어
- 실제 실행/테스트 결과
- 완료된 P0 / 미완료 P0 / 다음 할 일

## 품질 게이트
적어도 필수 사용자 흐름이 재현 가능하고, 데이터 입력 오류를 명시적으로 처리한다. 모든 테스트가 없으면 그 사실을 보고한다.

## 금지
무분별한 새 라이브러리, 임의 대규모 리팩터링, 원본 데이터 덮어쓰기, 사용하지 않은 외부 API를 사용한 척하기.
