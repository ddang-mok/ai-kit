# 해결 알고리즘 / 아키텍처 설계

## 입력
근거 기반 문제 정의, 사용 가능한 데이터, 요구사항 ID와 P0 기준, 환경 제약/평가기준.

## 절차
1. 출력할 결과, 사용자 입력, 데이터 계약(필수 필드/단위/유효성/결측 처리)을 명확히 한다.
2. 비교 가능한 baseline(단순 규칙·현재 절차·더미 모델 중 타당한 것)을 정한다. 기존 성능 측정 없으면 측정 계획만 기록한다.
3. 후보를 `규칙 기반 / 수리 최적화 / 통계 / ML / LLM·Agent` 중 실제로 적합한 것 2~4개 골라 비교한다. AI가 필요 없는 부분에 억지로 넣지 않는다.
4. 각 후보의 목표함수/KPI, 필수 데이터, 제약, 실패 조건, 비용/지연, 검증 방법을 비교한다.
5. 평가기준과 남은 구현 시간을 고려해 최소 복잡도 해법과 대안을 선택한다. 근거 없는 성능 예측은 가설로 표기한다.
6. UI/API/분석·모델/저장소/테스트의 최소 모듈 구성과 파일 변경 범위를 제안한다.
7. `P0→P1→P2` 의존관계, 데모 가능 수직 슬라이스, 단계별 인수 기준, 중단/폴백 계획을 수립한다.

## 출력
- 방법별 비교표(적합도/근거/구현 난이도/검증/리스크)
- 추천 해법과 선택 이유, baseline 정의
- 데이터 흐름 및 최소 아키텍처
- 구현 작업 순서(각 작업의 입력/출력/완료 테스트)
- 검증 매트릭스(`REQ-ID → 기능 → 테스트 → KPI`)

## 품질 게이트
P0 요구사항 모두에 실행 가능한 구현 단계와 검증 방법이 연결된다.

## 금지
이 단계에서 코드 수정, 임의 프레임워크 전환, 검증되지 않은 모델 정확도 주장.
