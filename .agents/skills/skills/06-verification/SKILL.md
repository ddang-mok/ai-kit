# 요구사항 / 성능 / 재현성 검증

## 입력
README 기반 요구사항 ID, 구현 결과, 테스트 명령어, 실제 데이터/검증 분리 계획, baseline.

## 절차
1. 기존 실행, 빌드, 단위/통합 테스트, 린트의 사용 가능 여부를 확인해 실제로 실행한다. 없는 것은 `미존재`로 쓴다.
2. `REQ-ID → 경로/함수/UI → 테스트 방법 → 결과` 추적 표를 완성한다.
3. 정상/경계/결측/중복/타입 오류/빈 입력/대용량/외부 API 실패 등 과제에 적합한 예외 케이스를 검증한다.
4. baseline과 개선안은 같은 데이터 분할·같은 제약·같은 평가 기준으로 비교한다. 차이, 표본 크기, 측정 조건을 기록한다.
5. 데이터 누수, 시간/집단 간 누출, 과적합, 재현 가능성, 개인정보/환경변수/시크릿 노출을 점검한다.
6. 실패나 미검증 항목을 숨기지 않고 심각도/재현 절차/수정 제안을 기록한다.
7. 시간이 부족하면 제출 가능성에 직접 영향을 주는 P0 실패부터 해결 우선순위를 제시한다.

## 출력
- 테스트 실행 명령과 실제 결과 요약
- 요구사항 추적/합격 판정 표
- 성능 비교(`관측값`/`측정 조건`/`한계`)
- 해결해야 할 결함 TOP 5
- `제출 가능 / 조건부 / 불가` 판정 및 이유

## 품질 게이트
실행되지 않은 테스트는 절대 PASS로 표시하지 않는다. 성능 숫자에는 검증 데이터 출처와 측정 조건을 붙인다.
