# 장애 대응 / 최소 수정 복구

## 입력
오류 메시지, 실행 명령, 최근 변경 파일, 환경/의존성, 예상한 결과와 실제 결과.

## 절차
1. 오류를 짧게 재현하고 재현 조건, 마지막 정상 상태, 영향 범위를 확인한다.
2. 스택트레이스/로그/종료 코드를 읽고 2~3개 원인 가설을 세운다.
3. 환경/경로/인코딩/의존성/데이터 스키마/코드 로직을 구분해 가장 값싼 읽기 전용 점검부터 수행한다.
4. `가설→검증→결과` 순서로 원인을 좁힌다. 아무 근거 없이 여러 파일을 한꺼번에 고치지 않는다.
5. 승인된 작업 범위 안에서 최소 수정하고, **실패 재현 테스트→수정→회귀 테스트**를 실시한다.
6. 기존 사용자 변경 사항은 보존한다. 리셋·삭제·강제 설치·비밀정보 노출은 하지 않는다.
7. 해결되지 않았으면 정확한 장애 상태와 폴백 경로, 다음 최소 진단 명령을 제시한다.

## 출력
- 오류 요약/재현 명령/영향 범위
- 근거에 따른 원인과 최소 수정 내역
- 수정 전후 테스트 결과
- 잔여 위험과 다음 행동

## 품질 게이트
재현 및 수정 후 검증 결과가 있어야 `해결`이라고 보고한다.
