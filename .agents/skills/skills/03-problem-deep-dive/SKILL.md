# 문제별 심층 분석

## 입력
README 요구사항 표, 1차 데이터 구조/품질 요약, 실제 KPI 정의 또는 후보.

## 절차
1. 사용자/이해관계자, 핵심 의사결정, 목표 KPI, 제약 조건을 다시 명시한다.
2. 목표 KPI의 분자/분모·집계 단위·기간·측정 방법을 정한다. 계산 불가하면 이유를 쓴다.
3. KPI 기준으로 그룹별·시간별·구간별 문제 집중도와 꼬리/이상치/전후 변화를 비교한다.
4. 실제 확인된 관측과 해석·가설을 분리한다. 데이터 누수, 혼란변수, 표본 편향, 선택 편향을 검토한다.
5. 잠재 원인 후보를 지지 근거/반대 근거/추가 검증 필요 항목과 함께 우선순위화한다.
6. 해결 기회의 크기(빈도, 영향, 데이터 가능성, 구현 가능성)를 비교한다. 수치가 없으면 정성 등급임을 표시한다.
7. 해결 방향이 다수라면 최소 2개 대안을 비교하고 가장 근거 있는 1개를 추천한다.

## 출력
- 문제 문장: `누가 / 어떤 상황에서 / 무엇을 / 어떤 제약 아래 개선할 것인가`
- KPI 정의 및 기존 baseline(계산 가능할 때만)
- 인사이트 TOP 5: 수치·근거·검증범위·불확실성
- 원인 가설 표: 지지/반대/확인 방법
- 우선 해결 과제 1~3개와 성공 조건

## 품질 게이트
핵심 인사이트가 적어도 하나의 측정 가능한 KPI 또는 명시적 제약과 연결되어야 한다.

## 금지
상관=인과 선언, 여러 집단을 뭉뚱그린 단정, 데이터가 없는 개선율 추정치를 성과처럼 기재.
