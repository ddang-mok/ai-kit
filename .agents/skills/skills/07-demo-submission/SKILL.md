# 데모 / 제출 / 평가 근거 정리

## 입력
공식 제출 규정, 구현/검증 보고서, 현재 Git 상태, 실행·시연 경로.

## 절차
1. 규정의 제출 파일, 경로, 크기, 기한, 실행 환경, 외부 의존성, 공개 가능 범위를 다시 점검한다.
2. 심사위원에게 보여줄 핵심 흐름을 **문제→입력→실행→결과→검증 근거→한계** 1~3분 시나리오로 구성한다. 시간은 과제 규정이 있으면 그에 맞춘다.
3. 새 환경 재현에 필요한 clone/setup/run/test 명령을 실제 환경과 비교한다.
4. `.env`, 토큰, 키, 고객/개인정보, 비공개 데이터가 Git 커밋에 포함되지 않는지 확인한다.
5. 평가지표별 주장과 확인 가능한 증거(테스트 로그·코드 위치·측정 결과)를 연결한다.
6. 오프라인/네트워크 실패/미설치 의존성에 대비한 폴백 데모 계획을 정한다. 가짜 데모를 실제 결과라고 주장하지 않는다.
7. README/제출 문서 수정 요청이 있을 때만 해당 문서를 작성·변경한다. 푸시/업로드/제출은 사용자가 명시적으로 요청할 때만 실행한다.

## 출력
- 제출 체크리스트(근거·충족·보완)
- 1~3분 데모 스크립트/실행 명령
- 평가항목별 근거 표
- 미해결 리스크·제출 전 필수 점검

## 품질 게이트
제3자가 명시된 명령으로 핵심 기능을 재현할 수 있어야 하며, 모든 성능 주장은 관측 결과만 사용한다.
