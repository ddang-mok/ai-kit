# 대회 시작 / 환경 점검

## 입력
공식 공지·규정·과제 README(있으면), 프로젝트 루트, 사용 가능한 개발 환경, 시간/토큰 제한.

## 절차
1. `pwd`, 최상위 파일 목록, Git 상태와 기본 실행 환경을 읽기 전용으로 확인한다. 환경 점검에 필요한 최소 명령만 사용한다.
2. 공식 규정의 허용·금지(인터넷, 공개 저장소, 모델, 라이브러리, 도구, 팀 협업, 제출 형식, 마감)를 출처와 함께 표로 만든다.
3. 평가 항목과 배점은 문서에 있는 것만 기록한다. 미제공 시 `미공개`로 적는다.
4. 사용자 요청과 제공 자료를 대조해 없거나 충돌하는 핵심 정보만 표시한다.
5. 다음에 읽을 README, 데이터, 코드의 순서를 정하고 최초 분석 단계로 연결한다.

## 출력
- 대회 제약/평가/제출 요약(항목-근거-상태)
- 개발 환경 점검 결과(확인/미확인)
- 파일 목록과 다음에 확인할 우선순위
- 가장 큰 리스크 3개 및 다음 단계

## 중단 기준
대회 규정 위반 위험이 있거나 저장소/도구의 데이터 외부 전송이 필요한 경우 행동 전에 사용자와 조건을 확인한다.

## 금지
이 단계에서 소스 수정, 외부 업로드, 라이브러리 설치, 테스트 실행으로 인한 변경, `git reset --hard` 등을 수행하지 않는다.
