# README/과제 요구사항 분석

## 입력
`README*`, 과제/규정 문서, 기존 소스 트리·설정 파일. README가 여러 개면 우선순위와 파일 경로를 명시한다.

## 절차
1. README, 제출 조건, 기술 제약, 데이터 설명, 실행 명령어를 읽는다. 불필요한 대량 파일 덤프는 하지 않는다.
2. 해결 대상 사용자/문제/기대 결과를 **근거 문장/파일 경로**와 함께 요약한다.
3. 요구사항 ID `REQ-01`부터 부여하고 **필수(P0)/핵심(P1)/선택(P2)/금지**로 구분한다. 이 분류가 주관적일 때는 `제안` 표시한다.
4. 평가기준·배점·마감·제출 형식은 실제 기재된 값만 기록하고, 누락은 `미명시`로 표시한다.
5. 실행 스택, 폴더 구조, 구현된 기능, 미구현 기능, 수정 주의 파일, 데이터 위치를 점검한다.
6. 충돌·불명확 사항을 구분하고, 데이터 점검 및 첫 MVP에 필요한 기준을 뽑는다.

## 출력
- 3줄 문제 정의
- `ID | 우선순위 | 요구사항 | 근거 파일/위치 | 완료 판정 방법 | 상태` 표
- `평가/제출/제약` 표 및 미명시 항목
- 현재 구조/실행 경로, 주요 리스크 TOP 5
- 다음 데이터 분석에 넘길 필수 질문과 주요 KPI 후보

## 품질 게이트
P0마다 완료 조건이 있어야 하며, 요구사항과 추정 제안이 구분되어야 한다.

## 금지
코드/데이터 수정, 근거 없는 배점 가정, 실제로 확인하지 않은 실행 성공 선언.
